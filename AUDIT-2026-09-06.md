# Gameplay and usability audit — 6 September 2026

Baseline: `4203bf8761db9513ef14028304332cf1000d0595` (main).

This is a confirmed-findings audit, not a guarantee that the application has no other bugs. Changes focus on the pure game engine, its callers, the rulebook and in-game help. Live account, marketplace, rewards and database behavior were not verified against production. No production data or game balance values were changed.

## Confirmed bugs and fixes

| Severity | Finding and reproduction | Fix |
| --- | --- | --- |
| High | Invoke a card as P1 while P2 has an affordable Quick answer. P2 holds priority, but P1 can invoke another Quick card or tap a Location anyway. The own-main timing shortcut bypasses the pending response. | Pending-stack invocation requires instant speed, held priority and an opponent's card to answer. Tapping a Location while a stack is pending also requires held priority. |
| High | Invoke a targeted Event without supplying a target. While a response is pending, make the previously preferred target Warded. Resolution picks a different unit, despite the rule that targets are chosen before responses. | Lock the automatic target when invoking, before costs and responses. A missing target cannot become a newly available target during resolution. The battle log now names automatic targets too. |
| Medium | Activate a Leader's targeted ability with a missing, friendly or Warded enemy target, or with no legal automatic target. The engine spends Resolve and the turn's activation even though the effect cannot apply. | Validate the target before any cost or activation mutation. Invalid actions return false without spending resources. |
| Medium | Invoke a Tool against a target that becomes Warded before resolution. Its bond succeeds, but its debuff silently switches to another enemy. Omitted Tool targets are also chosen too late. | Lock ordinary Tool targets on invocation, reject invalid explicit choices and let an illegal target invalidate only the debuff. The friendly bond still resolves. |
| Medium | Rules/help imply Unbreakable can save 0 Grit, describe remaining Grit as effective Grit, and incorrectly say Withering fires on leaving the field. Several engine comments still say once per turn. | Correct the rulebook, help and comments: once per game; 0 Grit and banish bypass the save; lethal-damage prevention leaves one Grit remaining; Withering applies through clash damage. |
| Low | The rulebook omits six shipped keywords and describes every invocation as stack-based, although Leader invocation/abilities resolve immediately. | Add Onslaught, Beacon, Dread, Kindle, Tailwind and Luminous. Explicitly describe the existing immediate digital actions, Leader limits and Resonant's existing second-effect auto-retargeting. |

Eight new regression cases cover the first four findings, including both explicit and automatic Tool targets. Seven initial cases failed on the baseline before fixes; the automatic Tool variant was added during follow-through. Existing tests were not weakened.

## Rules/gameplay checks

- Existing engine suites exercise opening hands, mulligans, essence payment, identity/deck legality, phase transitions, combat restrictions, guarded history, first/double strike, damage prevention, Items, Leader abilities, keywords, priority and stack resolution, visibility and randomized invariants.
- Read the canonical rulebook against stack/targeting, invoking, Leader, combat and state-check code. The fixes above close concrete discrepancies in those paths.
- Ran the full test suite and a seeded CPU match simulation: 8 decks, 2 games per ordered pairing, **112 completed games**, seed 1337. Engine invariants were clean, with no turn-limit draws. P1 won 54.5%; this small run is a correctness smoke test, not a balance verdict.
- **Intentional existing behavior now documented:** Leader invocation/abilities bypass the stack; Resonant may auto-retarget its second effect. Converting these to stricter paper-style stack/target rules would be a separate gameplay change.
- **Remaining engine integration caveat:** empty-stack Clash reaction ordering and the decision to finish the reaction window are driven by callers; this patch enforces priority while a card is pending. A future authoritative multiplayer endpoint must validate the actor and phase/window transitions instead of exposing the current headless control API directly.
- Tools with a separate targeted `onInvoke` still share the existing target-option interface; their additional subtype rider is automatically selected. Supporting two independently chosen targets needs an explicit multi-target UI/API.

## Quality-of-life and UI/UX

Implemented:

- Battle-log invocation lines now name automatic targets, including ordinary Tool debuffs, so players can understand what a pending card threatens.
- Event fizzle text covers targets that remain on the board but became illegal.
- In-game help distinguishes printed/effective Grit from remaining Grit, explains Unbreakable exceptions, and states Leader activation limits and immediate actions.

Recommended next, in priority order:

1. **Show each pending card's locked target in the stack panel.** Include a clear “target no longer legal” state after a response. The battle log now supplies the information; an inline target preview would make it easier to notice before passing.
2. **Offer separate target selection for Tool/Freeze-Dry riders.** Cards with several targeted effects need independently visible choices rather than implicit automatic selections.
3. **Generate rulebook keyword tables from `KW_REMINDER`.** In-game keyword help already uses the shared definitions; the standalone rulebook drifted. A generation/check step would prevent omissions without duplicating rule text.
4. **Finish a real desktop/mobile match audit before release.** Verify target selection, response/pass flows, keyboard focus, combat previews, narration and victory/rematch behavior using the existing browser harness. Avoid a large visual redesign until that evidence is available.
